# 《学生实训室进组选拔填报系统》需求设定 v1.1（定稿）

> 定稿日期：2026-11-09 · 来源：10 轮结构化需求访谈 · 定性：半自动选拔系统
> 上线死线：硬赶 11/2 08:00 填报开放前 · 架构：前后台共用单页应用（SPA）

---

## 0. 一句话定位
一个**半自动**的实训室进组选拔填报系统：系统负责数据采集、冲突检测、名额校验、实时递补顺延与调剂分配，**最终由导师/教务拍板**。前台（学生/导师）+ 后台（教务/负责人）。**系统从流程第 3 步"填报"开始管**，宣讲与开放日纯线下。

- 不是纯表单收集器，也不是全自动录取引擎。
- 系统自动算、人拍板；正常链路自动滚，异常才叫人。

---

## 1. 角色与权限矩阵（4 层）

| 角色 | 管辖 | 能做 | 不能做 |
|---|---|---|---|
| **学生** | 本人 | 填 ≤3 个平行导师志愿、勾服从调剂、多录取时选唯一去向、确认、本人申诉 | 提交后改志愿、确认后再反悔 |
| **导师** | 本人名下 | 初选、面试打分、定拟录取/递补/内部调剂候选名单、裁决本室冲突（正取谁随意） | 突破本人硬名额、提交后改名单 |
| **实训室负责人** | 本室 | **仅**运行时内部调剂协调（同室换导师）+ 异常兜底 | **不分配名额**、不跨室操作 |
| **教务** | 全院 | **定每个导师名额（Excel 导入）**、开合时间窗、跑统筹调剂、公示、强制推进/退回解锁/回填去向 | — |

> 核心铁律：**导师定"人"，名额定"量"**。导师可正取任意人、把别人挪去递补，系统尊重；但总数超名额一律硬拦。名额由**教务直分**（见 §8）。

---

## 2. 领域模型核心
- **硬名额挂导师级**，实训室名额 = 各导师之和。超发拦截、递补、内部调剂**全部按导师粒度算**。
- 核心实体：`学生` `导师` `实训室` `导师名额` `志愿` `选拔轮次` `拟录取/递补/内部调剂候选名单` `确认记录` `审计日志`。
- 模型是**选拔轮次为中心**（名额/志愿/匹配/状态流转），不是普通表单存储。

---

## 3. 学生状态机
```
待填报 → 已填志愿(锁定) → 已面试 → 拟录取(可能多个)
   → 待确认 → 已确认入组(锁定) ───────────────┐
   → 未录取 → 补录中(2~3轮) → 统筹调剂 → 入组 ┤→ 公示 → 正式入组
   → 落榜(标记+导出+教务线下回填) ────────────┘(不进公示)
```
- **确认**与**志愿填报提交**均为不可逆动作。
- 每个学生的终态只有两种：正式入组 / 落榜（线下）。无悬空态。

## 5. 关键业务规则
1. **志愿**：≤3 个平行导师志愿、不分先后；两个独立勾选（服从内部调剂 / 服从跨室调剂）。**提交即定不可改**，提交前强制**预览 + 二次确认**。
2. **超发拦截**：导师级硬名额，超 1 个都不让提交。
3. **多录取确认**：仅 1 个拟录取 → 自动确认；≥2 个 → 学生自选唯一去向。
4. **实时递补**：确认 → 空位 → 按预排顺序自动顺延；自动跳过已入组者；**被顶上者仍须确认**；仅"名单抽干 / 死结"两种异常才叫导师/负责人。
5. **确认即锁定**：不可反悔，后续补录/调剂只对未入组者开放。
6. **补录**：不重面试，沿用第 4 步成绩，纯"重新填志愿 + 名额匹配"，依次跑第二、三轮。
7. **统筹调剂**：服从即强制安置、不再问学生；两个服从勾选独立生效（只服从内部 → 绝不跨室）；优先级 ①同室换导师 ②跨实训室 ③服从者最终兜底。
8. **公示**：满 1 天无异议自动生效；只晒**姓名 + 录取实训室/导师**，成绩/志愿不公开。

---

## 6. 异常边界处理

| 场景 | 处理 |
|---|---|
| **落榜** | 全员名额 ≥ 总人数，落榜仅"没勾服从 + 没被录"者；标记未录取 + 导出 + 教务线下回填去向 |
| **学生逾期** | 视为放弃 → 触发实时递补 |
| **导师逾期** | 教务"强制推进"红按钮：按面试成绩兜底排序 / 标记异常跳过 |
| **并发抢名额** | 确认瞬间加锁校验、串行、先到先得，后到提示"名额已满"自动顺延 |
| **公示异议** | 仅学生本人申诉；成立 → 移出 + 留空线下，**不重跑**；教务回填去向 |
| **提交后填错** | 学生/导师改不了，只能走教务"退回/解锁" |
| **死结/环** | 连锁出现 A 等 B、B 等 A → 亮灯叫负责人/教务人工裁决 |
| **全程审计** | 每次提交/递补/调剂/回填/解锁留痕，作为异议追责底账 |

## 7. 基础设施
- **时间窗**：定时任务自动开合、**服务器时间为准**、教务应急提前/延时权。
- **数据/账号**：教务 **Excel 批量导入**底表（学生/导师/实训室/导师名额）；学号绑定预置账号、**首次登录强制改密**（防冒名）。

---

## 8. 名额分配机制（教务直分制 · Model B）
- **教务**：在 Excel 导入时**直接给每个导师填硬名额**，导入即生效。
- **导师**：在教务分给自己的硬上限内，自由决定录取谁、递补谁。
- **实训室负责人**：**不承担名额分配**；只在运行时做**内部调剂**（同室把学生从满的导师挪到空的导师）+ 异常兜底。
- 选型理由：Excel 导入天然带导师名额；硬赶 11/2，避免"负责人必须在填报前拆完名额"的上线前卡点。
